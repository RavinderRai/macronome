## Affected Pages/Routes

Mobile (Expo Android):
- **Onboarding flow** — height/weight/activity/goal collection → macro target computation → camera permission → sample-log demo
- **Today / Home** — daily macro ring, streak, recent meals (tappable for re-log)
- **Camera (plated meal)** — photograph meal → identification → ingredient list with portion controls → confirm → log
- **Camera (menu, restaurant mode ON)** — photograph menu → item extraction → per-item macros → rank by remaining → user picks → auto-log
- **Camera (pantry, restaurant mode OFF)** — photograph pantry contents → YOLO detection → VLM classification → confirmation → pantry update
- **Camera (receipt, restaurant mode OFF)** — photograph receipt → line item extraction → ingredient normalization → non-food filter → confirmation → pantry update
- **Recommendations** — fits-remaining-macros recipe list with diet-tag hard filter, pantry filter toggle, restaurant mode toggle, "Why this recipe?" chips
- **Pantry** — list, manual edit
- **Ask Macronome (chat)** — natural-language queries via existing 9-node workflow
- **Profile / goals** — macro targets, dietary constraints, allergies, streak history, dietary preferences (drives diet-tag filter)
- **Hidden dev dashboard** — long-press on profile → live MAE/MAPE/latency/cost panels

Backend (FastAPI):
- `/api/users` — onboarding, profile updates
- `/api/preferences` — diet types, dietary constraints
- `/api/pantry` — list, add, update, delete; receipt-scan endpoint (POST receipt photo → proposed deltas)
- `/api/meals` — log a meal (always traces to a photo), list logged meals, today's totals
- `/api/recommendations` — fit-remaining-macros recipes (params: pantry filter, restaurant mode, diet tags from profile)
- `/api/photos` — upload (with EXIF strip), signed URL retrieval
- `/api/menu/scan` — menu photo → per-item macros + rank
- `/api/chat` — Ask Macronome natural-language interface

## Key Interactions to Verify

- **Photo → log roundtrip:** snap → identify → ingredient list with editable portions (Small/Regular/Large + per-ingredient grams) → confirm → log appears on Today screen → daily totals update → recommendation list re-ranks
- **One-tap re-log:** tap a "Recent" meal → meal logs again with a fresh timestamp; photo lineage preserved
- **Restaurant mode toggle:** flip toggle on Log/Recommendations → secondary camera affordance changes (menu vs pantry+receipt) → recommendations swap to restaurant pool → photo→macros uses restaurant priors
- **Menu scan flow:** scan menu → extract items → chain detection on/off → per-item macros → rank by remaining macros → tap "I had this" → auto-logs
- **Receipt scan flow:** scan receipt → extract line items → normalize names → non-food filter → confirmation screen with proposed pantry deltas → user can edit → commit
- **Diet tag hard filter:** set "vegan" in profile → recommendations never include vegan-conflicting recipes
- **Pantry filter on recommendations:** toggle ON → only recipes whose ingredients are in pantry surface
- **Streak + completion ring:** log a meal → streak increments if today's first log → ring updates based on today's totals
- **Hidden dev dashboard access:** long-press on profile → dashboard opens → MAE/MAPE/latency panels render with real telemetry data
- **Onboarding macro computation:** complete onboarding → goals + macro targets persisted → Today screen reflects them

## Edge Cases

Photo flows:
- Multi-dish photo (single plate, multiple items): does the pipeline handle or degrade gracefully?
- Blurry photo / low light: what does the user see?
- Photo of non-food (random object): rejection or graceful "couldn't identify"?
- Network drops mid-upload: retry / clear error / no silent loss
- EXIF must always be stripped pre-storage (verify with a sample photo with embedded GPS)
- Very large photos (4K+): server-side resize before VLM call

Menu flows:
- Multi-page menu (only first page captured)
- Handwritten or non-English menu
- Menu in poor lighting / blurry / glare
- Menu of an unrecognized chain (independent restaurant fallback works)
- Menu with prices but no descriptions (extraction degrades)

Receipt flows:
- Receipts from chains not in the canonical mapping (LLM fallback fires)
- Bulk items (e.g., "5 LB CHICKEN BREAST") — quantity parsing
- Discount lines that aren't items
- Long receipts (50+ items) — pagination, performance
- Non-food on receipt (paper towels, light bulbs) — filter precision
- Loyalty IDs and payment last-4 must NOT be persisted (verify after extraction)

Macro tracking:
- Day rolls over at midnight (timezone correctness)
- Multiple meals logged simultaneously (race conditions on totals)
- Edited meal (delete + re-log)
- Negative remaining macros (user over-ate): UI handles, recommendation list still works (returns "no fit found" gracefully)

Recommendations:
- Zero recipes match (very strict diet + low remaining macros): empty state with helpful copy, not a crash
- 1000+ recipes match: pagination or top-N truncation
- Pantry filter ON with empty pantry: degrades to no-filter or shows "scan your pantry first"

Auth:
- Token expired mid-session
- User signed out on Settings → all stored data clears

Restaurant mode:
- Persisted across sessions: verify
- User toggles mid-photo (race condition): photo flow uses the mode at start, ignores toggles mid-flow

## Critical Paths (must not break)

1. **Sign in → onboarding → first meal log → see remaining macros.** First-run delight; if this breaks the user uninstalls.
2. **Photo of meal → ingredient list → log.** Daily-driver action. Must work every time on Android.
3. **Recommendations honor diet-tag hard filter.** Vegan user must never see meat in recs. This is a *trust* test, not a UX test — failure here costs the user trust permanently.
4. **Restaurant mode toggle does not corrupt macro tracking.** Switching the mode mid-day shouldn't double-count or drop logged meals.
5. **Pantry deltas from receipt scan are user-confirmed.** Never auto-write pantry without user review (avoids "AI added 50 random items to my pantry" failure).
6. **EXIF stripping always fires before any photo write.** Privacy-critical, no exceptions.
7. **Receipt photos are deleted within 24 hours of upload.** Privacy-critical, scheduled cleanup job must be reliable.
